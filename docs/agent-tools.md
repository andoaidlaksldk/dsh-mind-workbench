# 让 DSH 会话里的 Agent 直接画导图

本工作台除了自己的客户端面板，还向 DSH 会话**注册了三个可调用工具**，
所以你可以直接在对话里让 Agent 画导图、改导图，不必手动拖节点。

> 背景：只注册客户端面板是不够的——面板是本工作台自己的界面，不在 Agent 的能力清单里。
> 工具是服务端注册的，因此会出现在会话的可用能力中。

## 一、三个工具

| 工具 | 作用 | 参数 |
| --- | --- | --- |
| `mindmap_list` | 列出工作台里的导图文档（id、名称、更新时间），并指出画布当前打开的是哪一个 | 无 |
| `mindmap_read` | 把一份导图读成 Markdown 大纲；不传 `documentId` 就读画布当前打开的那份 | `documentId`（可选） |
| `mindmap_write` | 用 Markdown 大纲新建或覆盖一份导图 | `outline`（必填）、`name`、`documentId` |

## 二、大纲写法

`mindmap_write` 接受 Markdown：`#` 是主题，`##` 是一级分支，列表用两个空格表示更深一层。

```
# 周会纪要
## 进展
- 完成 A
- 完成 B
## 风险
- 依赖排期
## 下周
- 联调
```

上面的写法会得到一个 7 个节点的导图。缩进越深，节点层级越深；不写 `#` 时，
工具会用你给的主题名（或 `name` 参数）作为根节点。

## 三、可以这样对 Agent 说

- 「把这次讨论整理成思维导图，写进 DSH 思维导图工作台」
- 「读一下我当前打开的导图，把『风险』那一支补全」
- 「把这份周报改成导图：……」
- 「列出工作台里所有导图，然后打开第一个」

## 四、写完怎么看到

`mindmap_write` 直接写 DSH 数据目录，画布不会自己知道。因此：

1. 工作台面板会**每 4 秒**检查一次当前导图是否被画布之外的写入更新，
   一旦发现就显示提示：「当前导图已被外部更新（例如 Agent 写入）」；
2. 点提示里的 **「重新载入」**（或工具栏的「重新载入」）即可看到 Agent 画好的导图。

> 为什么不做自动重载：画布自己保存时也会更新 `updatedAt`，
> 自动重载会在保存的一瞬间误判并丢掉正在编辑的内容。宁可让你点一下。

## 五、实现位置与依赖

- 工具注册：`dsh/index.js` 里的 `registerMindMapTools()`，通过
  `ctx.inject(['tools'], …)` 注册；`tools` 服务缺失时只是工具不注册，插件本体照常加载。
- 工具定义用官方的 `defineTool`（`@deepseek-ai/dsh-tools`，已在 `peerDependencies` 声明）。
- 大纲 ⇄ 导图的转换在同文件的 `outlineToMindMap()` / `mindMapToOutline()`，由 `verify.mjs` 断言。
- `mindmap_write` 生成的导图使用画布源码默认主题与 `logicalStructure` 结构；覆盖已有文档时保留它原本的主题与结构。
